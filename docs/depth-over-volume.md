# Depth Over Volume

When too many things are active at once, each receives a first pass and none
receives the attention needed to become dependable. The visible output may
increase, but the work becomes thinner: context is rebuilt repeatedly, obvious
answers survive because there is no time to challenge them, and finishing is
replaced by moving on.

The goal is not to produce the most. It is to make what is produced matter.

## Choose What Deserves Depth

Not every task deserves the same investment. Before committing deeply, name the
outcome, who needs it, and what being excellent would change.

Give depth to work where careful thinking changes the result: a difficult
decision, an investigation whose answer others will rely on, a message that
will shape shared understanding, or a change that will be expensive to undo.
Handle routine work simply and correctly. Depth is valuable because it is
selective.

## Make Fewer Commitments

Every commitment competes for attention before any work begins. It creates
context to remember, people to update, decisions to revisit, and an unfinished
state to carry.

Do not add work merely because it is useful. Ask whether it is more useful than
what is already underway. If something new must begin, name what will pause,
move, or stop.

A list of priorities is incomplete until it also says what will not be done
now.

## Stay Past the First Plausible Answer

Volume rewards the first answer that appears reasonable. Depth stays with the
work long enough to test whether that answer is true.

Re-read the evidence. Follow the dependency one step further. Test the failure
path, not only the successful one. Ask what a reviewer or user will need that is
obvious now only because the context is still fresh.

This is not permission to polish indefinitely. Define what a dependable result
requires, meet that standard, and stop.

## Finish the Whole Outcome

Depth includes the final, less interesting parts of the work: verifying the
result, writing down what changed, closing open questions, and making the
outcome usable by someone who was not present.

Starting several valuable things can feel more productive than completing one.
It is not. Unfinished work has not yet delivered the value used to justify
starting it.

Finish one meaningful outcome before expanding the field of work again. When
the work is genuinely blocked, record the exact blocker and restart point
before choosing the next commitment.

## Protect Attention from Useful Distractions

The hardest distractions to refuse are not trivial. They are worthwhile ideas,
reasonable requests, and improvements that would be good to make. Their value
does not make them timely.

Capture useful work without immediately adopting it. A backlog preserves an
idea; starting it spends attention. Treat those as different decisions.

## Practical Routine

- At the start of the week, name no more than three outcomes that would make
  the week successful. Write them as completed results, not areas of activity.
- Keep one substantial outcome in progress at a time. Put everything else under
  "Next" or "Later" rather than treating the whole list as active.
- Before starting a focus block, write the question to answer, the evidence to
  produce, and what will count as done.
- Give important work a protected sixty- to ninety-minute block. Close messages
  and unrelated tabs, and leave one narrow route for something genuinely
  urgent.
- Keep a parking list beside the work. Record new requests and ideas there
  instead of switching immediately.
- When accepting new work, state the trade-off aloud: "I can start this after
  X," or "I can start this now if Y moves."
- End each block by recording the result, the remaining unknown, and the exact
  restart point. Do not make the next session rebuild the same context.
- At the end of the week, count finished outcomes rather than started tasks.
  Remove or defer work that remained active without meaningful progress.

## Review Questions

- What are the few outcomes that deserve my best attention now?
- Which active commitment is making the others shallower?
- What will pause or stop if I accept something new?
- Have I tested the first plausible answer, or only found it?
- What remains before this outcome is dependable and usable by someone else?
- Am I improving the result, or polishing because I have not defined done?
- Which useful distraction should be recorded rather than started?
